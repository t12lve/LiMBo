# LiMBo v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Livrer LiMBo v1 sur Windows 11 : extension Chromium MV3 YouTube (qualité + trim) communiquant en WebSocket avec une app Tauri qui télécharge via yt-dlp/FFmpeg, avec build `/dev` → `/prod`.

**Architecture:** Extension client léger + Desktop-centric (Tauri). Contrat JSON dans `@limbo/shared`. Serveur WS `127.0.0.1:4567`, JobRunner séquentiel (yt-dlp → FFmpeg), cold-start via `limbo://open`.

**Tech Stack:** pnpm workspaces, TypeScript, Vite, React, Tailwind, Tauri v2 (Rust), Chrome MV3, yt-dlp, FFmpeg, Vitest (shared).

## Global Constraints

- OS v1 : Windows 11 uniquement
- Sources uniquement sous `dev/` ; livrables uniquement sous `prod/`
- Port WS fixe : `4567` sur `127.0.0.1` seulement
- Zéro écran Réglages ; premier lancement Desktop = choix dossier sortie puis mémorisé
- YouTube vidéo unique seulement (pas de playlists, pas de sniff réseau)
- Extension ne parse jamais les signatures YouTube — yt-dlp seule source de vérité
- Un job actif à la fois
- Packages npm : `@limbo/shared`, `@limbo/desktop`, `@limbo/extension`
- Commits fréquents ; identité git one-shot si besoin : `git -c user.name="t12lve" -c user.email="2hellv@gmail.com"`

describe("parseTimecode", () => {

  });
  it("parses hh:mm:ss", () => {

  it("rejects garbage", () => {

describe("validateTrim", () => {
  it("accepts valid range", () => {
    expect(validateTrim(10, 60, 120)).toEqual({ ok: true });
  });
  it("rejects end <= start", () => {
    expect(validateTrim(60, 60, 120).ok).toBe(false);
  });
  it("rejects beyond duration", () => {
    expect(validateTrim(0, 200, 120).ok).toBe(false);
  });
});

describe("formatTimecode", () => {
  it("formats seconds", () => {
    expect(formatTimecode(90)).toBe("01:30");

- Produces: serveur WS démarré au setup Tauri ; gère `hello` / `auth` ; broadcast channel pour events jobs (stub `jobs.snapshot` vide pour l’instant)

Protocole (aligné `@limbo/shared`) :
1. Client envoie `{ "type": "hello" }`
2. Serveur répond `{ "type": "hello.ok", "token": "..." }`
3. Client envoie `{ "type": "auth", "token": "..." }`
4. Si OK → `{ "type": "auth.ok" }` puis accepte commandes ; sinon fermer

Bind strict : `127.0.0.1:4567` (pas `0.0.0.0`).

- [ ] **Step 1: Implémenter `ws_server::start(token, job_tx)` dans une tâche tokio**

- [ ] **Step 2: Test manuel avec un client jetable**

Depuis PowerShell (avec Desktop lancé), script Node minimal dans `dev/scripts/ws-smoke.mjs` :
```js
import WebSocket from "ws";
const ws = new WebSocket("ws://127.0.0.1:4567");
ws.on("open", () => ws.send(JSON.stringify({ type: "hello" })));
ws.on("message", (d) => {
  const msg = JSON.parse(d.toString());
  console.log(msg);
  if (msg.type === "hello.ok") {
    ws.send(JSON.stringify({ type: "auth", token: msg.token }));
  }
  if (msg.type === "auth.ok") {
    console.log("AUTH_OK");
    process.exit(0);
  }
});
```
Run: `node scripts/ws-smoke.mjs`  
Expected: logs `hello.ok` puis `AUTH_OK`

- [ ] **Step 1: `build-extension.mjs`**

```js
import { cpSync, rmSync, mkdirSync } from "node:fs";
import { spawnSync } from "node:child_process";
import path from "node:path";

const root = path.resolve(import.meta.dirname, "..");
const repo = path.resolve(root, "..");
const out = path.join(repo, "prod", "extension");
spawnSync("pnpm", ["--filter", "@limbo/extension", "build"], {
  cwd: root,
  stdio: "inherit",
  shell: true,
});
rmSync(out, { recursive: true, force: true });
mkdirSync(out, { recursive: true });
cpSync(path.join(root, "apps/extension/dist"), out, { recursive: true });
console.log("Wrote", out);
```
